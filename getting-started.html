Build and verify

Build and verify

Pinned toolchain leanprover/lean4:v4.35.0 (lean-toolchain), Mathlib at cfc55fc, brownian-motion at 61de83c; the nested package contrib/ is a Lake path dependency.

git clone https://github.com/chenle02/airy1-gumbel-lean
cd airy1-gumbel-lean
lake exe cache get          # Mathlib build cache
lake build Airy1Gumbel Airy1GumbelContrib
lake env lean AxiomCheck.lean > transcript.txt
python3 scripts/audit.py transcript.txt

scripts/audit.py checks that AxiomCheck.lean prints axioms for exactly the theorems declared in Airy1Gumbel/, that no proof escape (sorry, admit, axiom, …) occurs, and that every theorem depends only on propext, Classical.choice and Quot.sound. verify.sh (and contrib/verify.sh) run the same check from a fresh build, with two negative controls, and write the log that a lean-pkg receipt binds to one commit.

Comparator check of the headline

Challenge.lean restates Theorem 1.1 in Mathlib vocabulary, in two forms (mixing assumed on the continuous version, or on the coordinate process); its objects are defined, without proofs and from Mathlib only, in ChallengeDefs/Airy1Gumbel/: the Airy function, the kernels of the Quastel-Remenik path integral, the entire Fredholm determinant, the distribution functions airy1FinCdf, the three named inputs and the normalization. The law and the continuous version are not constructed there: each statement asserts that an Airy₁ law exists, and that for such laws a version continuous on [0, ∞) exists and the Gumbel limit holds for every such version (in the first form for every law and every continuous version satisfying the mixing input; in the second for every law whose coordinate process satisfies it). The check verifies the headline under the three inputs, not the inputs. Solution.lean proves both statements from the package headlines, and comparator.json is the configuration the comparator checks (each Solution theorem has exactly its Challenge type and uses only the three standard axioms):

lake build ChallengeDefs Challenge Solution

Comparator check of the contrib package

Since v0.3.1 the contrib package has its own comparator configuration, contrib/comparator.json: the 103 theorem claims of contrib/claims.yaml up to v0.7.0, one Challenge theorem Airy1GumbelLeanContribAudit.<decl> each. The theorem claim added in v0.8.0 (box-cdf-measure, the finite-box measure constructor) is internal and is not compared, and its module FddMeasure/BoxCdf.lean is not in the copied library. contrib/Comparator/Challenge.lean states them (76 as the elaborated types Lean prints, 27 as the declarations' own source statements) over contrib/Comparator/Defs, a verbatim copy of the library that imports Mathlib modules only; contrib/Comparator/Solution.lean proves each by the copied library theorem, and neither file imports the library. contrib/scripts/comparator/CheckFidelity.lean checks with Expr equality that every copied constant equals the library's and every Challenge statement equals the claimed declaration's type. From contrib/:

lake build Airy1GumbelContrib Comparator.Challenge Comparator.Solution
lake env lean --run scripts/comparator/CheckFidelity.lean

To use the library from another Lake project:

[[require]]
name = "airy1-gumbel-lean"
git = "https://github.com/chenle02/airy1-gumbel-lean"
rev = "v0.8.0"
